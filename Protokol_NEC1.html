1. Systemoversigt

Systemet består af én server og to klienter, der simulerer temperatursensorer. Kommunikation foregår over tre protokoller: TCP til primær dataudveksling, UDP til alarmbeskeder og HTTP til dataindsigt via browser. Kommunikation initieres af begge parter over TCP-forbindelsen.

Protokol Port Formål Klasser
TCP 6000 Primær dataudveksling — vejrmålinger og serverkommandoer WeatherServer, ClientHandler, WeatherClient
UDP 7000 Alarmnotifikationer ved høj temperatur UdpAlarmSender, UdpAlarmReceiver
HTTP 8080 JSON-endpoint til dataindsigt i browser HttpServer

2. TCP-protokol — port 6000

2.1 Kommunikationsflow

Klienten forbinder til serveren via TCP. Serveren accepterer forbindelsen og sender straks en velkomstbesked. Herefter sender klienten løbende vejrmålinger. Serveren sender en alarmkommando tilbage over samme forbindelse, hvis temperaturen overskrider 35 °C. 

  WeatherClient (SENSOR-1)              WeatherServer / ClientHandler
          |                                         |
          |------- TCP connect() :6000 ------------>|   (TCP-forbindelse etableres)
          |                                         |
          |<------ "CONNECTED:Server klar" ---------|   (server → klient)
          |                                         |
          |------- "SENSOR-1,34.21,62.08,174..." -->|   (klient → server)
          |------- "SENSOR-1,33.80,65.44,174..." -->|
          |------- "SENSOR-1,36.83,58.11,174..." -->|   (temp > 35°C)
          |<------ "ALARM:Høj temperatur 36.83" ----|   (server → klient)
          |------- "SENSOR-1,31.55,70.22,174..." -->|
          |                  [...]                  |
          |                                         |
          |   (forbindelsen lukkes ved fejl/afslut) |
Begge retninger er aktive over den samme TCP-forbindelse. Serveren initierer CONNECTED og ALARM. Klienten initierer den løbende datastrøm. Dette opfylder kravet om tovejskommunikation.

2.2 Pakkeformat — WeatherData (klient → server)

Hver måling sendes som én linje tekst i UTF-8, afsluttet med linjeskift (\n). Felter er separeret med komma. Linjen parses af serveren med WeatherData.fromMessage(). 

FORMAT:   SENSOR-ID,TEMPERATUR,LUFTFUGTIGHED,TIMESTAMP

EKSEMPEL: SENSOR-1,34.21748392,62.0837140,1748412345678
Felt Java-type Eksempelværdi Beskrivelse
SENSOR-ID String SENSOR-1 Unik identifikator for den afsendende sensor
TEMPERATUR double 34.217 Temperatur i °C — simuleret mellem 30 og 45 °C
LUFTFUGTIGHED double 62.083 Relativ luftfugtighed i procent — simuleret 40–80 %
TIMESTAMP long 1748412345678 Tidsstempel i millisekunder siden Unix-epoke (System.currentTimeMillis())

2.3 Pakkeformat — serverkommandoer (server → klient)

Serveren sender kommandoer til klienten som én linje tekst med formatet TYPE:BESKED, afsluttet med linjeskift.

Kommandotype Format Eksempel Hvornår
CONNECTED CONNECTED:<besked> CONNECTED:Server klar Straks når TCP-forbindelsen accepteres
ALARM ALARM:<besked> ALARM:Høj temperatur 36.83 Når modtaget temperatur overskrider 35,0 °C

2.4 Trådhåndtering

Serveren accepterer klientforbindelser i en løkke i WeatherServer.start(). For hver ny klient startes en dedikeret tråd med ClientHandler som Runnable: 

  // WeatherServer.start()
  while (true) {
      Socket clientSocket = serverSocket.accept();   // blokerer til klient forbinder
      new Thread(new ClientHandler(clientSocket, storage)).start();
  }

Klienten (WeatherClient) implementerer ligeledes Runnable. Dens run()-metode sender vejrdata i en løkke. Parallelt startes en daemon-tråd (listenerThread), der læser indgående serverkommandoer fra samme socket-forbindelse: 

  // WeatherClient.run()
  Thread listenerThread = new Thread(() -> listenForCommands(reader));
  listenerThread.setDaemon(true);   // afsluttes automatisk når JVM lukker
  listenerThread.start();

  while (true) {
      writer.println(data.toMessage());   // send vejrdata
      Thread.sleep(SEND_INTERVAL_MS);
  }
Daemon-tråde afsluttes automatisk, når alle non-daemon-tråde er stoppet. Det sikrer, at listener-tråden ikke forhindrer programmet i at afslutte.

3. UDP-protokol — port 7000

3.1 Kommunikationsflow

Når ClientHandler modtager en vejrmåling med temperatur over 35 °C, sender UdpAlarmSender en DatagramPacket til port 7000. UdpAlarmReceiver kører som daemon-tråd på serveren og læser fra samme port. 

  ClientHandler                      UdpAlarmReceiver (port 7000)
        |                                     |
        |   (temp > 35.0°C modtaget)          |
        |                                     |
        |-- DatagramPacket → UDP :7000 ------->|
        |   "ALARM! Høj temperatur: 36.83°C   |
        |    fra SENSOR-1"                    |
        |                                     |  *** ALARM MODTAGET: ... ***

3.2 Pakkeformat — UDP alarm

UDP-pakken indeholder en enkelt fritekst-streng kodet i UTF-8. Modtagerbufferen er sat til 1024 bytes, hvilket er mere end tilstrækkeligt for en alarmbesked.

Felt Type Maks. størrelse Eksempel
Alarmbesked UTF-8 tekst 1024 bytes ALARM! Høj temperatur: 36.83°C fra SENSOR-1
Valg af UDP: UDP er forbindelsesfri og garanterer ikke levering eller rækkefølge. Det er bevidst valgt her fordi alarmbeskeder er korte og hurtige, og fordi en enkelt tabt pakke ikke er kritisk — næste måling vil generere en ny alarm. UDP demonstrerer samtidig et klart alternativ til TCP i samme system.

4. HTTP-protokol — port 8080

4.1 Kommunikationsflow

HttpServer er implementeret direkte på ServerSocket uden biblioteker. Den læser og kasserer HTTP-request-linjerne, og svarer med et JSON-array over alle gemte vejrmålinger. 

  Browser / HTTP-klient                     HttpServer (port 8080)
          |                                         |
          |--- "GET / HTTP/1.1\r\n" -------------->|
          |    "Host: localhost:8080\r\n"           |
          |    "\r\n"  (tom linje = header-slut)    |
          |                                         |  (læser request, bygger JSON)
          |<--- "HTTP/1.1 200 OK\r\n" --------------|
          |     "Content-Type: application/json\r\n"|
          |     "Connection: close\r\n"             |
          |     "\r\n"                              |
          |<--- [JSON-array]                        |
          |                                         |  (socket lukkes)

4.2 Response-format (JSON)

Svaret er et JSON-array. Hvert element repræsenterer én gemt vejrmåling i den rækkefølge, de er modtaget: 

[
  {
    "sensor":      "SENSOR-1",
    "temperature": 34.217483921,
    "humidity":    62.083714,
    "timestamp":   1748412345678
  },
  {
    "sensor":      "SENSOR-2",
    "temperature": 38.912,
    "humidity":    55.321,
    "timestamp":   1748412346123
  }
]
JSON-felt Java-kilde Type Beskrivelse
sensor WeatherData.getSensorId() String Sensor-ID fra den afsendende klient
temperature WeatherData.getTemperature() number (double) Temperatur i °C
humidity WeatherData.getHumidity() number (double) Luftfugtighed i procent
timestamp WeatherData.getTimestamp() number (long) Unix-tidsstempel i millisekunder

5. Trådsikkerhed — ReadWriteLock

Flere tråde tilgår WeatherStorage simultant: én ClientHandler-tråd per klient (skriver) og HttpServer-tråden (læser). For at undgå race conditions anvendes ReentrantReadWriteLock.

5.1 Lock-strategi

Metode Lås-type Adfærd
save(WeatherData) Write lock Kun én tråd kan skrive ad gangen. Alle læsende tråde blokeres midlertidigt.
getAll() Read lock Flere tråde kan læse samtidig, så længe ingen holder write lock.
getLatest() Read lock Samme princip som getAll().

5.2 Implæmentation

Låsen frigives altid i en finally-blok for at garantere frigivelse selv ved undtagelser:

  // Skrivning (ClientHandler-tråd)
  lock.writeLock().lock();
  try {
      dataList.add(data);
      // skriv til fil ...
  } finally {
      lock.writeLock().unlock();   // frigives altid
  }

  // Læsning (HttpServer-tråd)
  lock.readLock().lock();
  try {
      return new ArrayList<>(dataList);   // returnerer kopi
  } finally {
      lock.readLock().unlock();
  }
getAll() returnerer en ny ArrayList-kopi i stedet for direkte reference. Det sikrer, at kalderen ikke kan ændre den interne liste uden for låsen.
